# GoF 23 种设计模式速查(下午题第五/六题 + 上午题常考)

> 出题规律:上午题给意图描述选模式名;下午题给类图填代码空。
> 记忆锚点:先记三大类,再记每类"谁在什么时候干什么"。

## 创建型(5 种)— "对象怎么生"

| 模式 | 一句话意图 | 常考辨析 |
|---|---|---|
| 单例 Singleton | 全局仅一个实例,提供统一访问点 | 私有构造 + 静态方法;线程安全写法 |
| 原型 Prototype | 克隆已有实例创建新对象 | `clone()`;深拷贝/浅拷贝 |
| 工厂方法 Factory Method | 定义创建接口,子类决定实例化哪个类 | 一个工厂产一种产品;对比抽象工厂 |
| 抽象工厂 Abstract Factory | 创建**一系列相关**产品,不指定具体类 | 工厂产**产品族**;加新产品难、加新系列易 |
| 建造者 Builder | 分步组装复杂对象,同过程可造不同表示 | Director + Builder;区别于工厂的"分步" |

## 结构型(7 种)— "对象怎么拼"

| 模式 | 一句话意图 | 常考辨析 |
|---|---|---|
| 适配器 Adapter | 转换接口,让不兼容类协作 | 类适配(继承)/对象适配(组合);补历史漏洞 |
| 桥接 Bridge | 抽象与实现分离,各自独立变化 | 两维变化(形状×颜色)用桥接;多维度继承爆炸的解药 |
| 组合 Composite | 树形结构,部分-整体一致处理 | 透明/安全式;文件-文件夹模型 |
| 装饰器 Decorator | 动态加职责,比继承灵活 | 包一层同接口;与适配器区别:不改接口只加职责 |
| 外观 Facade | 给子系统一个统一高层入口 | 简化调用;与中介者区别:外观是单向简化 |
| 享元 Flyweight | 共享细粒度对象省内存 | 内部状态共享、外部状态外部传;棋子/连接池 |
| 代理 Proxy | 控制对原对象的访问 | 远程/虚/保护代理;与装饰器区别:代理管访问、装饰管加功能 |

## 行为型(11 种)— "对象怎么协作"

| 模式 | 一句话意图 | 常考辨析 |
|---|---|---|
| 模板方法 Template Method | 父类定骨架,子类填步骤 | 抽象父类 + 钩子方法;最常考的代码填空 |
| 策略 Strategy | 封装可互换的算法族,客户端替换 | 排序算法切换;与状态区别:由客户端设 vs 状态机自转 |
| 状态 State | 状态改变时行为随之改变 | 状态机;类图与策略几乎一样,看谁驱动切换 |
| 观察者 Observer | 一对多依赖,状态变化自动通知 | Subject/Observer;事件系统 |
| 职责链 Chain of Responsibility | 请求沿链传递直到被处理 | 审批流;与组合区别 |
| 命令 Command | 把请求封装成对象,支持撤销/排队 | Invoker/Command/Receiver;宏命令 |
| 备忘录 Memento | 保存并恢复对象状态而不破坏封装 | Originator/Memento/Caretaker;撤销功能 |
| 迭代器 Iterator | 顺序访问聚合内部而不暴露结构 | `next()/hasNext()`;与聚合分离 |
| 中介者 Mediator | 用中介对象封装网状交互 | 聊天室/塔台;与外观区别:中介是双向解耦 |
| 解释器 Interpreter | 给定语言,定义其文法的解释器 | 正则/规则引擎;少用但上午题偶考 |
| 访问者 Visitor | 不改结构,给元素加新操作 | 双分派;结构稳定+操作多变 |

## 下午题代码填空套路

1. 先看类图:抽象层(抽象类/接口)→ 具体实现层的继承或组合关系;
2. 空 1、空 2 通常考**继承声明**(`extends/implements`)与**成员变量类型**(应写抽象类型而非具体类型——多态);
3. 中段空考**方法委托**(调用组合对象的接口方法);
4. 结尾空考**对象的创建**(常是 `new 具体类()` 放在工厂/客户端里);
5. Java 版注意接口方法必须 public;C++ 版注意虚函数与析构函数虚化。

## 设计原则(SOLID,上午题考"违反了哪条")

| 缩写 | 原则 | 一句话 |
|---|---|---|
| SRP | 单一职责 | 一个类只有一个变化的理由 |
| OCP | 开闭 | 对扩展开放,对修改关闭(考试出现频率最高) |
| LSP | 里氏替换 | 子类必须能透明替换父类 |
| ISP | 接口隔离 | 不强迫客户依赖用不到的方法 |
| DIP | 依赖倒置 | 依赖抽象,不依赖具体实现 |
