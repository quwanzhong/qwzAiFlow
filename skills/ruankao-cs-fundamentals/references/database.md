# 数据库

## 范式判定(设计表结构时先过这一关)

| 范式 | 要求 | 一句话判据 |
|---|---|---|
| 1NF | 属性原子性 | 字段不可再拆(拆"联系方式"为电话/地址) |
| 2NF | 消除部分函数依赖 | 非主属性必须依赖**整个**候选键(联合主键时警惕) |
| 3NF | 消除传递依赖 | 非主属性之间不能互相依赖再传给主键 |
| BCNF | 主属性也不能有依赖 | 每个决定因素都是候选键 |

工程口诀:**"每个字段依赖键,整个键,除了键别无其他"**。
反范式是性能优化手段(冗余读多写少的数据),但要接受一致性与更新成本。

## E-R 模型转关系模式

- 实体 → 一个关系模式,属性照搬。
- 联系:
  - **1:1**:并入任一端,把另一端主键作外键;
  - **1:n**:并入 n 端,把 1 端主键作外键;
  - **m:n**:必须**单独建表**,主键 = 两端主键的组合。
- 判联系类型:问"一个 A 对应几个 B,一个 B 对应几个 A"。

## SQL 要点

- 执行顺序:**FROM → JOIN/ON → WHERE → GROUP BY → HAVING → SELECT →
  DISTINCT → ORDER BY → LIMIT**。WHERE 里不能用 SELECT 别名/聚合函数
  (那是 HAVING 的事)—— 排错先看这个。
- JOIN:INNER 只留匹配;LEFT 保留左表全部(右表填 NULL)。
  "查没有订单的用户" → LEFT JOIN + `IS NULL`,或 NOT EXISTS。
- NULL 陷阱:`NULL = NULL` 结果是 NULL 不是真;判空必须 `IS NULL`;
  `NOT IN` 子查询含 NULL 时整个返回空 → 用 `NOT EXISTS`。
- 聚合:GROUP BY 后 SELECT 只能出现分组列与聚合函数。
- 视图:虚表简化权限与复杂查询;物化视图预计算换性能。

## 事务与并发

ACID:原子性(全做或全不做)、一致性(完整性约束不被破坏)、隔离性
(并发互不干扰)、持久性(提交即落盘)。

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| READ UNCOMMITTED | 有 | 有 | 有 |
| READ COMMITTED | 无 | 有 | 有 |
| REPEATABLE READ(MySQL 默认) | 无 | 无 | InnoDB 用间隙锁基本无 |
| SERIALIZABLE | 无 | 无 | 无 |

三类问题定义:脏读 = 读到别人**未提交**的数据;不可重复读 = 同一行两次读值
不同(他人 UPDATE);幻读 = 同一条件两次读**行数**不同(他人 INSERT)。

## 索引

- 底层 B+ 树:矮胖(3~4 层撑千万行)、叶子成链表支持范围扫描;
  对比:哈希索引快但无范围、B 树非叶存数据导致范围差。
- 失效场景(评审检查项):对索引列用函数/运算、隐式类型转换(字符串列传数字)、
  前导 `%` 的 LIKE、`OR` 连接非索引列、联合索引不满足**最左前缀**。
- 建索引原则:WHERE/JOIN/ORDER BY 高选择性列;写多读少的表慎加;
  联合索引把等值列放前、范围列放后。

## 其他高频

- 关系代数:投影 π(选列)、选择 σ(选行)、连接 ⋈;除法 ÷ = "查询全部…"类语义。
- 完整性:实体完整性(主键非空唯一)、参照完整性(外键)、用户自定义(CHECK)。
- 触发器:事件-条件-动作(ECA);存储过程:预编译 SQL 集合,减少网络往返。
- 备份:完全/增量/差异;日志先写(WAL)是崩溃恢复的根基。
