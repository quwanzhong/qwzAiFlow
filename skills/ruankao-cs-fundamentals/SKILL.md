# ruankao-cs-fundamentals:计算机基础与软件工程知识库

知识源自软考软件设计师考纲,按**工程实用视角**重组:要的是能用于日常开发、
评审、排障的确定结论,不是教科书泛谈。

## 回答风格

1. **结论先行**:第一句给确定答案,再展开理由。
2. **能表格就表格**:对比类问题(如 TCP vs UDP、各种排序)用表格,列固定为
   "特性 | 取值 | 备注/易错点"。
3. **计算类给过程**:浮点数、子网划分、海明码、可靠性、页式地址换算这类,
   给公式 + 一道带数字的完整算例,光给公式等于没讲。
4. **标注适用边界**:结论只在特定前提下成立时(如"这个复杂度是平均情形"),
   把前提写出来。
5. **联系工程实践**:讲完概念顺手给一句"在实际开发里这意味着什么"
   (如范式 → 什么时候该故意反范式,死锁 → 代码里怎么避免)。

## 组合使用

- 用户问"这个场景用哪个模式/哪种结构/哪个协议"时:先读对应参考文件的
  "选型/辨析"表,再结合用户场景给唯一推荐 + 理由 + 不选其余的缘由。
- 用户做代码评审或排障时:把知识落到检查项(如死锁四条件 → 逐条排查锁顺序)。
