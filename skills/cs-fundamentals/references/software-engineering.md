# 软件工程(含 UML 与知识产权实务)

## 开发模型选型

| 模型 | 特征 | 适用 | 风险 |
|---|---|---|---|
| 瀑布 | 线性顺序,文档驱动,阶段评审 | 需求明确稳定 | 返工代价大 |
| 原型 | 快速造原型确认需求 | 需求不明确 | 用户把原型当成品 |
| 增量 | 分批交付可用子集 | 核心先行、可分期 | 需要良好架构拆分 |
| 螺旋 | 迭代 + **风险分析**驱动 | 大型高风险项目 | 风险分析人力成本高 |
| 敏捷(Scrum/XP) | 短迭代、拥抱变化、可工作软件优先 | 需求多变、小团队 | 依赖自律与客户参与 |

选择口诀:**需求明不明决定要不要原型;风险大不大决定要不要螺旋;
能不能分期决定增量还是瀑布**。

## 需求与设计

- 需求工程:获取 → 分析(分类建模)→ 定义(SRS)→ 验证(评审)。
  SRS 特性:正确、无二义、完整、一致、可验证、可追踪。
- 需求分类:功能需求 / 非功能需求(性能、安全、可用性…)/ 设计约束。
- 模块独立性度量:**耦合(模块间,越低越好)**:数据 < 标记 < 控制 < 公共 <
  内容耦合;**内聚(模块内,越高越好)**:偶然 < 逻辑 < 时间 < 过程 < 通信 <
  顺序 < 功能内聚。评审口诀:**高内聚低耦合**。
- 结构化设计:数据流图(DFD)分层细化;加工 = 变换/事务流。
- 测试:
  - 白盒覆盖强度:**语句 < 判定 < 条件 < 判定/条件 < 条件组合 < 路径覆盖**;
  - 黑盒:等价类、边界值(必测 0/空/最大)、错误推测、因果图;
  - 阶段:单元(编码期,开发做)→ 集成(自顶向下/自底向上/三明治)→
    系统 → 验收(用户做);α 在开发方场地,β 在用户方;
  - McCabe 环路复杂度 **V(G) = 边数 − 节点数 + 2 = 判定节点数 + 1**,
    衡量独立路径条数。
- 维护四类:改正性(修 bug)~ 适应性(环境变)~ 完善性(加功能,**占比最大**)
  ~ 预防性。可维护性 = 易理解 + 易修改 + 易测试。

## UML 速查

14 种图 = 结构(静态 7)+ 行为(动态 7)。

- **用例图**:参与者-用例;关系:**include(必含子流程)、extend(可选扩展)、
  泛化(继承)**。include 是箭头指向被包含用例且**必执行**;extend 可选执行。
- **类图**:关系由弱到强:**依赖 < 关联 < 聚合 < 组合 < 泛化(实现)**。
  - 聚合(空心菱形):整体没了部分还在(部门-员工);
  - 组合(实心菱形):同生共死(人-心脏);
  - 实现 = 虚线三角,泛化 = 实线三角。
- **顺序图**:生命线 + 激活条 + 消息(同步实心箭头/异步开放箭头/返回虚线)。
- 状态图:状态 + 转移(事件[条件]/动作);适合描述单个对象生命周期。
- 活动图:类流程图,可泳道分职责;描述业务流程/并行。
- 部署图(节点=硬件)↔ 构件图(构件=代码单元)。

## 知识产权实务(开发中真用得上)

- **著作权自动取得**,作品完成即享有;软件著作权保护**程序与文档**,
  不保护思想/算法/编程语言。自然人为**死后 50 年**(12.31 止);法人为
  **首次发表后 50 年**;署名权等人身权无限期。
- **职务作品/职务发明**:主要利用单位物质技术条件或执行任务完成 →
  著作权/专利权归单位,作者有署名权 —— 接私活与开源前先想清楚这条。
- 专利:发明 20 年、实用新型 10 年、外观设计 15 年,自**申请日**起算;
  专利保护思想方案,软件可结合硬件/方法申请发明专利。
- 开源协议要点:Apache 2.0/MIT/BSD 宽松(可闭源,保留声明);GPL 传染
  (衍生品必须开源);LGPL 库引用可闭源。商用选型先看协议。
- 商标 10 年可续展;商业秘密靠保密措施维持,无限期但被反向工程不侵权。

## 质量与配置管理

- CMMI 五级:初始 → 已管理 → 已定义 → 量化管理 → 优化。
- 软件质量特性(McCall/ISO 25010):功能性、可靠性、易用性、效率、维护性、
  可移植性 —— 评审非功能需求时对着挑。
- 配置管理:配置项基线(功能基线/分配基线/产品基线)、版本控制、变更控制
  委员会(CCB)、配置审计。
- 风险管理:识别 → 估算(风险曝光度 = 概率 × 损失)→ 应对(规避/转移/
  缓解/接受)→ 监控。
