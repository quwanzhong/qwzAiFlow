# GoF 23 种设计模式与 SOLID

> 给"意图描述"选模式,给"场景"推荐结构 —— 下面每张表就是速查索引。

## 创建型(5)— 对象怎么生

| 模式 | 一句话意图 | 常考/常用辨析 |
|---|---|---|
| 单例 Singleton | 全局唯一实例,统一访问点 | 私有构造 + 静态方法;注意线程安全(双重检查/枚举) |
| 原型 Prototype | 克隆已有实例创建新对象 | `clone()`;注意深拷贝/浅拷贝 |
| 工厂方法 Factory Method | 定义创建接口,**子类**决定实例化哪个类 | 一个工厂一种产品;新增产品要新工厂 |
| 抽象工厂 Abstract Factory | 创建**一系列相关**产品族,不指定具体类 | 加新产品族易、加新品种难;与工厂方法就差在"族" |
| 建造者 Builder | 分步组装复杂对象,同过程造不同表示 | Director + Builder;链式配置(如 StringBuilder 亦此神) |

## 结构型(7)— 对象怎么拼

| 模式 | 一句话意图 | 辨析 |
|---|---|---|
| 适配器 Adapter | **转换接口**,让不兼容类协作 | 类适配(继承)/对象适配(组合);接旧接口、第三方库 |
| 桥接 Bridge | 抽象与实现分离,两维独立变化 | 形状×颜色、消息类型×通道;治继承爆炸 |
| 组合 Composite | 树形结构,部分-整体一致处理 | 文件-文件夹、UI 组件树 |
| 装饰器 Decorator | **不改接口**,动态叠加职责 | Java IO 流;与适配器区别:不改接口只加职责 |
| 外观 Facade | 给子系统一个统一高层入口 | 单向简化调用;SDK 的门面类 |
| 享元 Flyweight | 共享细粒度对象省内存 | 内部状态共享、外部状态外传;连接池/棋子 |
| 代理 Proxy | **控制访问**原对象 | 远程/虚(懒加载)/保护代理;与装饰器:代理管访问权限,装饰管加功能 |

## 行为型(11)— 对象怎么协作

| 模式 | 一句话意图 | 辨析 |
|---|---|---|
| 模板方法 Template Method | 父类定骨架,子类填步骤 | 钩子方法;最经典的继承复用 |
| 策略 Strategy | 封装可互换算法族,客户端替换 | 支付方式/排序策略;if-else 大军的解药 |
| 状态 State | 状态改变时行为随之改变 | 状态机;与策略类图同形:**谁驱动切换**——客户端=策略,自身流转=状态 |
| 观察者 Observer | 一对多依赖,变化自动通知 | 事件/订阅发布;GUI、消息队列的原型 |
| 职责链 Chain of Responsibility | 请求沿链传递直到被处理 | 审批流、过滤器链、中间件 |
| 命令 Command | 请求封装成对象,可撤销/排队/日志 | 撤销重做、任务队列 |
| 备忘录 Memento | 保存/恢复状态而不破坏封装 | 编辑器快照 |
| 迭代器 Iterator | 顺序访问聚合内部而不暴露结构 | `next()/hasNext()`;for-of 背后 |
| 中介者 Mediator | 用中介封装网状多向交互 | 聊天室、塔台;与外观:中介双向解耦,外观单向简化 |
| 解释器 Interpreter | 给定语言定义文法与解释器 | 规则引擎、DSL;少用 |
| 访问者 Visitor | 不改结构给元素加新操作 | 双分派;结构稳定+操作频繁变化 |

## 选型决策树

1. 是创建问题吗?→ 唯一实例=单例;复制=原型;单产品多变体=工厂方法;
   产品**族**=抽象工厂;分步组装=建造者
2. 是结构问题吗?→ 接口不兼容=适配器;两维变化=桥接;树=组合;加功能=装饰器;
   简化入口=外观;省内存=享元;控访问=代理
3. 是行为问题吗?→ 算法可换=策略;状态驱动=状态;通知=观察者;层层审批=职责链;
   撤销=命令+备忘录;骨架固定=模板方法;网状解耦=中介者

## SOLID 原则(评审时对号入座)

| 缩写 | 原则 | 一句话 | 违反信号 |
|---|---|---|---|
| SRP | 单一职责 | 一个类只有一个变化理由 | "God 类"、类名含 And |
| OCP | 开闭 | 对扩展开放、对修改关闭 | 加功能要改老 if-else |
| LSP | 里氏替换 | 子类能透明替换父类 | 子类抛异常/弱化前置条件 |
| ISP | 接口隔离 | 不强迫依赖用不到的方法 | 空实现、接口臃肿 |
| DIP | 依赖倒置 | 依赖抽象不依赖具体 | new 具体类散落各处 |

其他常考:合成复用(优先组合而非继承)、迪米特法则(只和朋友说话,最少知识)。

## 代码题套路(给类图写实现)

1. 先分抽象层与实现层,认出"组合/聚合/委托"的成员变量(类型写**抽象类型**,多态);
2. 继承用 `extends/implements`;持有对方引用即关联(构造注入);
3. 模板方法:骨架方法 final,步骤方法 abstract;
4. 策略/状态:Context 持有 Strategy 接口,行为委托 `strategy.doSomething()`;
5. 观察者:Subject 持有 Observer 列表,notify 循环调 `update()`。
