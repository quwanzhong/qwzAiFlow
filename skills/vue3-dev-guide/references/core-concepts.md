# Vue 3 核心原理

在响应式、组件更新、生命周期、异步竞态、渲染性能或 SSR 问题中读取本文件。

## 响应式状态

- `ref` 适合独立值、可能整体替换的对象以及需要稳定传递的响应式引用；脚本中访问或修改使用 `.value`，模板会自动解包。
- `reactive` 适合围绕同一业务一起变更的结构化状态。不要直接替换整个代理对象，也不要随意解构其属性，否则可能丢失响应联系；需要解构时使用 `toRef`、`toRefs` 或保持对象访问。
- 不要为所有值套多层响应式包装。外部复杂实例或不应代理的对象，应先检查项目是否使用 `shallowRef`、`shallowReactive` 或 `markRaw`。
- `computed` 表达由现有状态推导出的值。getter 应保持纯净，不发请求、不写状态、不操作 DOM。
- `watch` 用于明确数据源引起的副作用；`watchEffect` 适合依赖自然产生且逻辑简短的副作用。不要用深度监听代替清晰的数据流。
- 异步监听必须使旧结果失效或取消。为兼容不同 Vue 3 版本，优先使用 watch 回调提供的 cleanup 能力；只有确认项目 Vue 版本支持时才使用较新的清理 API。
- 注意更新是批量调度的。只有确实需要读取更新后的 DOM 时才使用 `nextTick` 或调整 watcher 的 flush 时机。

## 组件边界

- props 是外部只读输入。组件内部需要编辑时，创建明确的本地草稿或通过事件请求父组件更新。
- 声明组件能够发出的事件；事件名和参数应表达业务意图，不暴露组件内部实现。
- 默认 `v-model` 契约是 `modelValue` 与 `update:modelValue`。只有项目版本和既有代码允许时才采用更新的宏语法。
- 插槽适合由父组件决定结构的可变区域；普通数据优先用 props，不要让作用域插槽承担隐蔽的数据服务职责。
- `provide`/`inject` 适合跨越多层、边界明确的上下文能力，不替代普通 props、Store 或模块依赖。
- composable 应封装可复用的有状态逻辑和完整生命周期；保持输入、返回值和副作用清晰，避免变成杂乱的工具集合。

## 生命周期与副作用

- setup 阶段创建响应式状态；挂载后才能访问依赖真实 DOM 的对象。
- 在卸载阶段清理定时器、事件监听、观察器、订阅、外部实例和未完成请求。
- 避免在 `updated` 中无条件修改触发当前更新的数据，以免形成循环。
- `KeepAlive` 下组件可能只是停用而非卸载；需要区分 activated/deactivated 与 mounted/unmounted 行为。
- 浏览器 API、DOM 和持久化访问在 SSR 中必须有环境边界，且每个请求必须拥有隔离状态，避免交叉请求污染。

## 渲染与列表

- 模板优先于手写渲染函数；只有高度动态且模板难以清晰表达时才使用 `h` 或 JSX。
- `key` 表示节点身份，不只是消除警告。排序、插入、删除或复用表单项时使用稳定、唯一的业务 ID。
- `v-if` 控制是否创建节点，适合切换频率较低或初始不需要渲染的内容；`v-show` 只切换显示状态，适合高频切换。
- 避免在同一元素上混用 `v-if` 与 `v-for`。先通过 computed 筛选数据，或用外层 `<template>` 表达结构。
- 不要直接操作由 Vue 管理的 DOM；需要集成第三方 DOM 库时，通过 template ref 和生命周期建立清晰边界。

## 内建能力

- `defineAsyncComponent` 用于真实的代码拆分或延迟加载，并配置合理的 loading、error、timeout 与重试体验。
- `KeepAlive` 仅缓存确实需要保留状态的动态组件，并明确 include/exclude 和缓存失效规则。
- `Teleport` 适合弹窗、浮层等需要脱离当前 DOM 层级的内容；逻辑归属仍属于原组件树。
- `Transition`/`TransitionGroup` 负责进入、离开和列表过渡；动画不能阻塞交互，并尊重项目现有动效规范。

## 性能判断

- Vue 编译器会进行静态提升、补丁标记和事件缓存等优化。先写清晰模板，不要重复框架已有优化。
- 优先检查不稳定 key、巨大响应式对象、无边界深度 watch、重复请求、过大的组件和不必要的全局状态。
- 路由页面和重型模块按项目规范懒加载；不要把所有小组件都异步化。
- Tree-shaking 依赖静态 ESM 结构和可判定的副作用。避免无必要的全局注册和具有隐式副作用的模块入口。
