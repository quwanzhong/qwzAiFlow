# Vue 3 开发指南

为 Vue 3 工程提供贴合现有项目的实现指导。先理解项目，再选择 Vue API；不要把参考资料中的示例机械套入代码。

## 开始前

1. 使用 UTF-8 阅读当前目录及上级目录中的 `AGENTS.md`。
2. 检查 `package.json`、锁文件、构建配置、目录结构和相似页面，确认：
   - Vue 主版本和具体版本；
   - JavaScript 或 TypeScript；
   - Composition API 或 Options API；
   - 路由、状态管理、请求库、UI 库和测试框架；
   - 项目已有的组件、组合式函数、样式变量和错误处理方式。
3. 以当前项目和用户需求为准。未经要求，不升级 Vue、构建工具或依赖，不切换状态管理或 UI 库，不重写现有架构。
4. 默认直接完成需求范围内的代码修改；默认不编译、运行、启动项目或更新快照，除非用户明确要求。

## API 风格决策

- 新建的完整 Vue 3 应用或独立组件，在项目没有相反规范时，优先使用单文件组件、Composition API 和 `<script setup>`。
- 存量 Options API 项目继续遵循原有风格；不要只为“现代化”而整页改写。
- 仅在项目已经采用 TypeScript 时新增对应类型；不要擅自把 JavaScript 项目迁移到 TypeScript。
- 先复用项目已有抽象。只有出现重复的有状态逻辑且抽取后边界清晰时，才创建 composable。
- 不从旧资料引入 Vue 2 API。涉及旧代码时，按 [Vue 2 兼容与迁移](references/vue2-compatibility.md) 判断。

## 实现原则

- 保持单向数据流：父组件通过 props 输入，子组件通过声明过的 emits 输出；不要直接修改 props。
- 局部状态留在组件，跨页面或真正共享的业务状态才进入 Pinia；服务端数据不要无条件复制到全局 Store。
- `computed` 用于派生值并保持纯净；`watch`/`watchEffect` 用于副作用，并清理过期请求、定时器和监听器。
- 列表使用稳定且唯一的业务 `key`；可排序、插入或删除的列表不要使用数组索引或随机值作为 `key`。
- 异步流程必须覆盖加载、成功、空数据、业务失败、网络异常、重复提交和组件卸载后的失效结果。
- 路由、权限、请求、Store、页面和展示组件保持职责边界；不要把所有业务逻辑堆在页面组件中。
- UI 优先复用项目组件库、设计令牌和已有页面；样式应限制作用域并处理小屏、长文本、溢出和安全区域。
- 谨慎使用 `v-html`、全局状态、全局组件和深度监听；只有明确收益时才使用。
- 优化前先定位真实瓶颈；理解 Vue 的响应式依赖、调度、虚拟 DOM 和编译优化，但不要手工模拟框架内部机制。

## 按任务读取参考资料

- 页面、表单、接口、路由、Pinia 或 UI 开发：读取 [应用开发工作流](references/application-workflow.md)。
- 响应式、生命周期、组件通信、列表更新、异步组件、性能或 SSR 问题：读取 [Vue 3 核心原理](references/core-concepts.md)。
- 发现 `new Vue`、`Vue.extend`、过滤器、Vuex、旧生命周期或旧事件总线：读取 [Vue 2 兼容与迁移](references/vue2-compatibility.md)。
- 需要确认知识来源、时效或版本边界：读取 [资料来源与时效](references/sources.md)。

只读取当前任务需要的参考文件，不要一次性加载全部内容。

## 交付要求

- 修改范围保持最小，不覆盖用户已有改动，不修改无关文件。
- 说明修改了哪些文件、关键实现、兼容性判断和建议验证场景。
- 如果需求、接口或设计存在会改变实现方向的歧义，明确指出；能从项目中确认的信息不要反复询问。
